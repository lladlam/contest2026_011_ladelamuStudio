# 主动智能架构与安全边界

## 1. 目标

主动智能不是固定时间脚本，也不是让大模型直接控制设备。当前实现把决策拆为四层：

```text
家庭实时状态
  -> 板端候选生成
  -> 板端实时增量画像与安全门
  -> 匿名学习统计同步
  -> 按需云端深度校准
  -> 板端再次校验并等待用户确认
  -> MIoT 属性写入与真实状态确认
```

板端是最终裁决者。无网络、服务超时、模型返回非法 JSON、建议过期或情境已变化时，
云端结果自动失效，界面继续使用本地算法。云端不能获得设备 DID、账号、房间名、
设备名、令牌或任意工具调用能力，也不能直接下发 MIoT 指令。

## 2. 当前可用能力

当前实现三类可解释候选：

- 冷启动示例：结合可靠时钟、灯光、空调状态和用户反馈生成睡眠准备建议。它只用于
  在没有行为历史时解释交互流程，不限制真实模式中的触发类型。
- 时间习惯：观察用户在相近时间对可写属性的真实操作，至少跨 5 个不同自然日后
  才形成候选。
- 事件联动：任意已同步的布尔值、数值或设备在线状态变化，都可作为触发条件；
  观察该变化后 10 分钟内的人工操作，至少重复 3 次后形成
  “触发状态 -> 延迟 -> 动作属性”候选。连续数值按有界区间匹配，避免温度等
  轻微波动把同一习惯拆成大量规则。

每条通用习惯拥有稳定规则 ID、观察/接受/拒绝次数、时间均值、平均偏差、事件延迟
和自动化状态。用户可选择“仅本次执行”“设为自动”“仅今天忽略”或“以后少提醒”。
“设为自动”后规则仍只控制本地已经验证的低风险属性，且每次执行前重新解析当前
设备、在线状态、属性权限和数值范围。门锁、摄像头、传感器、燃气和报警设备可以
提供触发状态，但不能成为学习动作目标。执行失败不会删除规则，也不会伪造成功
反馈。

真实画像使用 CRC 与双槽记录持久化；旧版画像按版本迁移，不兼容或损坏记录安全
回到冷启动。演示回放使用同一个核心但与真实画像隔离，不上传云端学习数据。

## 3. 本地算法

板端采用有界、可解释的在线估计，不进行危险的随机探索：

1. 首次全量同步只建立基线，只有后续真实 MIoT 增量变化进入学习。
2. 系统自身下发并确认的变化带自生成标记，不反向训练自身。
3. 时间规律按不同自然日累计；事件规律按独立发生次数累计。同一动作会关联
   10 分钟窗口内所有不同触发源，不再只取一个最近事件。
4. 接受、拒绝和自动化执行结果实时更新画像，并立即进入持久化和匿名同步队列。
5. 跨午夜时间使用平移后的分钟坐标求平均，避免 23:55 与 00:05 被算成中午。
6. 置信度由独立天数、重复证据和反馈组成；连续拒绝会降低置信度和提醒频率。
7. 事件联动在证据增长后逐渐降低对固定时刻的依赖，使规则能够随生活节奏迭代。
8. 时钟无效、目标不可解析、属性不可写或高风险设备命中时不产生可执行动作。

这对应 contextual bandit 的 Context、Action、Reward 思路，但当前不宣称实现了
LinUCB 或完整强化学习。Vowpal Wabbit 的官方说明将 contextual bandit 定义为
观察情境、选择动作、只获得所选动作反馈的循环；其离线策略评估文档也强调上线前
应使用日志评估候选策略。本项目因此保留事件回放和现场反馈，但禁用自动探索。

参考：

- <https://vowpalwabbit.org/tutorials/contextual_bandits.html>
- <https://vowpalwabbit.org/tutorials/off_policy_evaluation.html>
- <https://proceedings.mlr.press/v108/wu20c.html>

## 4. 云端顾问

普通学习更新发送以下匿名字段：

```text
profile_revision/routine_id/routine_kind/update_kind
observation_count/accepted_count/rejected_count/confidence
mean_minute_of_day/mean_deviation_minutes/mean_delay_seconds
automation_enabled
```

这里的 `routine_id` 只是板端生成的规则序号，不是设备标识。服务端使用会话保险箱
密钥以 AES-GCM 加密保存匿名画像，不存 DID、设备哈希、名称、账号、房间或原始
事件。普通更新只写画像；只有新规则、置信度跨阈值、明确拒绝或明显时间漂移才建议
调用模型。周期复核至少间隔 10 分钟，每会话默认每天最多 6 次。

两类 AI 请求使用不同 Skill：

- 开发板经鉴权 HTTPS 发起实时候选分析时，服务端加载
  [`d13x-board-ai`](../skills/d13x-board-ai/SKILL.md)。模型密钥不进入固件，
  此 Skill 只允许评估板端已经构造的匿名候选。
- 服务端对长期匿名画像、能力清单或习惯漂移做自主分析时，加载
  [`d13x-server-ai`](../skills/d13x-server-ai/SKILL.md)。此 Skill 只能建议证据
  门槛、置信度和观察策略，不能生成设备动作。

服务程序直接读取仓库内 `SKILL.md` 并注入对应模型请求，OpenClaw 和 MiLoco
只用于参考 Skill 形式与设备盘点调用方式，不是生产运行依赖。开发板请求的模型
结果限制为：

```text
decision: propose | suppress | defer
action_policy:
  turn_off_selected_light_keep_ac |
  turn_off_selected_light |
  execute_local_candidate |
  notify_only |
  none
requires_confirmation: true
```

通用时间/事件规则只允许返回 `execute_local_candidate`，云端不能替换 SIID、
PIID 或目标值。置信度调整限制在 -10 至 +10，结果有效期限制在 60 至 1800 秒，
文本长度和条数均有限制。服务端缓存相同情境。模型超时、HTTP 错误、解析失败、
预算耗尽或越权字段都会返回本地降级结果；网络中断不停止板端继续学习。

配置只允许从服务状态目录的 `private/agent-llm.env` 读取。该文件必须由服务用户
所有、权限不超过 `0600`，且只识别以下变量：

```text
AGENT_LLM_BASE_URL=<private HTTPS endpoint>
AGENT_LLM_API_KEY=<private key>
AGENT_LLM_MODEL=<private model name>
AGENT_LLM_TIMEOUT_SECONDS=12
```

真实值不得写入仓库、固件、串口日志、测试附件、PR 或 Release。

## 5. 本地安全门

云端结果到达后，板端再次验证：

- 登录会话仍有效；
- 网络状态仍在线；
- `decision_key` 与当前情境一致；
- 单调时钟未超过结果有效期；
- 本地建议仍存在；
- 当前仍有在线、可写的目标设备；
- 云端策略属于本地允许集合；
- 未启用自动化的操作仍需用户点击确认；
- 自动化必须已由用户在板端明确启用，并通过本地安全设备白名单。

最终设备 DID、SIID 和 PIID 只在板端确认阶段绑定。云端返回的自然语言不能被解释
为命令，也不能替换本地目标。

## 6. 故障行为

| 故障 | 预期行为 |
| --- | --- |
| 无网线或无互联网 | 不请求云端，使用本地算法 |
| 云端超时或 5xx | 显示本地降级，不阻塞触摸和同步 |
| 底层云端线程异常挂起 | 20 秒后停止阻塞本地建议；旧结果仍受情境键和有效期约束 |
| JSON 非法或字段越界 | 丢弃结果，使用本地算法 |
| 模型日预算耗尽 | 只保存匿名学习更新，使用本地算法 |
| 情境在等待期间变化 | 旧 `decision_key` 结果失效 |
| 结果超过有效期 | 重新评估，不沿用旧建议 |
| 本地安全条件不足 | 云端不能把 suppress 改成执行 |
| 用户未确认新规则 | 不启用自动化 |
| MIoT RPC 失败 | 不记录接受反馈 |

## 7. 后续演进

开发机可执行以下只读验证。工具调用本机 MiLoco 读取设备列表和规格，本地生成能力
清单，上传前删除 DID、设备名、账号和真实房间；`--cloud` 只额外发送匿名聚合：

```bash
cd ../mijia
.venv/bin/python -m mijiaAPI.proactive_inventory --cloud \
  --state-dir /home/lladlam/OpenVela/Data/mijia-server
```

后续可将云端长期校准扩展为下发有界阈值版本，但板端仍必须保留候选规则、画像、
冷却、安全门和离线动作确认。若升级为线性 contextual bandit，必须先用脱敏日志
做离线策略评估，并保持家电动作零随机探索。
