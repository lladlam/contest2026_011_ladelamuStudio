# 主动智能测试

## 主机核心测试

```bash
./tests/proactive/run.sh
```

预期输出 `proactive tests: PASS`。该测试不依赖 LVGL 或开发板，覆盖冷启动、七天
回放、接受与拒绝统计、真实/模拟画像隔离、导入导出、时间规律、同日多次事件
规律、布尔/数值/在线状态触发、数值区间匹配、自生成事件隔离、离线自动化和学习
同步队列。它只能证明决策核心，不能替代实机 UI、Flash 和 MIoT 验收。

## 实机步骤

1. 烧录当前候选镜像，等待有线网络、NTP 和米家家庭模型同步完成。
2. 打开一盏在线且可写的米家灯具，进入左侧“智能”页面。
3. 点击“回放 7 天”，确认界面始终显示“演示模式｜模拟历史数据”，约 25 秒后
   进入“演示模式｜第 8 天”，有效历史为 7 天，建议置信度随反馈上升。
4. 检查解释中包含当前睡眠时段、开启灯数和相似情境接受率；建议动作应指向真实
   在线灯具，空调已开启时应明确写“保留空调运行”。
5. 点击“仅今天忽略”，确认建议消失且页面、触摸、米家同步继续响应。
6. 点击“返回真实”，确认恢复回放前的正式画像，演示统计不会保留；再次回放后
   点击“执行建议”，确认先显示“等待设备状态确认”，目标灯真实关闭
   后由 MIoT 增量状态刷新界面。发送失败或指令忙时不得记录为接受。
7. 点击“重置画像”，随后在真实运行模式记录一次反馈；等待串口出现
   `[HOME][AGENT] profile persist ret=0`，完全断电 10 秒后上电并确认画像恢复。
8. 再执行一次模拟回放并反馈，断电重启，确认恢复的仍是回放前真实画像。
9. 在家庭、房间、智能页面往返 500 次，回放期间持续触摸，确认无明显延迟、
   页面重建风暴、RISC-V exception 或设备误操作。
10. 在真实模式分别制造以下非睡眠行为并重复至少 3 次：门磁或设备在线状态变化
    后操作灯具、温湿度进入相近区间后调整可写设备、同一天重复触发同一联动。
    再次制造触发状态，确认出现“设备联动建议”，而不是“睡眠准备”。
11. 验证摄像头、门锁、传感器和报警设备的状态可以进入触发上下文，但其可写属性
    不会出现在建议动作或“设为自动”的目标中。

## 云端与离线降级

1. 保持网络和米家会话在线，进入“智能”页面并触发建议。确认出现
   `[HOME][AGENT] learning synced` 与 `[HOME][AGENT] cloud analysis requested`。
   普通观察应只同步学习统计，只有新规则、跨阈值、拒绝冲突或漂移触发模型复核；
   分析期间触摸、切页和设备增量同步必须继续响应。
2. 云端允许建议时，“执行建议”仍必须由用户点击，不能自动控制设备。
3. 在建议出现后拔掉网线，或停止服务端进程。确认断网后立即保留本地建议；
   即使底层请求没有返回，最多 20 秒后也不能继续阻塞“执行建议”。确认没有
   崩溃、没有重复创建工作线程，并且恢复网络后能重新评估。
4. 在云端请求期间改变目标灯状态。旧结果返回后不得作用于新情境，界面应基于新
   的 `decision_key` 重新分析。
5. 等待云端建议超过有效期，确认旧建议不再匹配当前情境。
6. 检查串口日志和抓包：不得出现 API key、Bearer token、保险箱密码、设备 DID、
   用户名、二维码 URL 或大模型完整响应。

架构、安全边界和故障矩阵见
[`docs/PROACTIVE_INTELLIGENCE.md`](../../docs/PROACTIVE_INTELLIGENCE.md)。

## 预期串口关键行

```text
[HOME][AGENT] profile cold-start ...
[HOME][AGENT] profile persist ret=0 ...
[HOME][AGENT] profile restored ret=0 ...
[HOME][AGENT] learning synced revision=... routine=... cloud-review=...
[HOME][AGENT] cloud analysis requested ...
```

串口日志、视频和镜像 SHA-256 按 `VALIDATION.md` 归档。演示数据必须在界面和
答辩说明中明确标注，不能描述为实际运行七天所得。
